# Интервью 28 auto-apply-and-hotkey

Протокол: вопросы по порядку, каждый обсуждается один раз. Факты и позиции —
`design.md`; здесь — формулировка вопроса, позиция и решение. Ответы
записываются по мере обсуждения (`@NikolayXHD` / `@pi-agent`).

## Вопросы на старте

1. **Граница авто-применения.** Решено из постановки (см. «Принятые
   решения», п. 1): всё, что накручено до первой сборки промпта, применяется
   само.

2. **Объём авто-применения.** Решено из постановки (п. 2): весь.

3. **Клавиша хоткея применения.** Ограничение @NikolayXHD: shift-комбинации
   не годятся — половина сетапов терминального эмулятора их не передаёт.
   Решение: применение — `ctrl+alt+r` (@NikolayXHD); `alt+r` остаётся за
   кольцом статусных переменных. pi сама использует `ctrl+alt+` комбинации
   (`tui.editor.jumpBackward` = `ctrl+alt+]`), синтаксис поддержан. Поведение
   хоткея — как у кнопки «update current session context»: применить,
   обновить статус, уведомить; вне интерактивного режима ничего не делать
   (как существующие хоткеи).

   Требования @NikolayXHD к сохранению текущих возможностей (критерии
   приёмки):

   - `!` на смене модели/переменной и на правке исходника остаётся и в
     промежутке до первой сборки промпта: статус показывает, что текст
     отличается от того, что в промпте;
   - кнопка «rewrite files on disk» остаётся: пишет текущую версию в цели
     для чтения, ничего не применяя.

4. **Хоткей-переключение посреди сессии.** Решено из постановки (п. 4): без
   авто-применения, трение снимает хоткей применения.

## Принятые решения

1. Промежуток до первой сборки промпта (создание сессии → первое сообщение):
   применяется всё, что накручено (переменные, model/level, правки
   исходников, `template.json`). Применённая версия фиксируется на первой
   сборке промпта; применённая версия `session_start` остаётся точкой
   отсчёта для метки `!` (статус в промежутке — как сейчас). Правило
   «применение — явное действие» работает с первого хода и дальше.
2. Объём авто-применения в промежутке — весь: правило без исключений
   (из постановки: «автоматическое применение шаблона — строго верное
   решение»).
3. Посреди сессии хоткей-переключение не применяет контекст само; трение
   снимает второй хоткей — применение к контексту без открытия меню (из
   постановки).

## Ответы

### 1. Граница авто-применения

Решение: из постановки @NikolayXHD — «для изменений перед стартом сессии
автоматическое применение шаблона — строго верное решение». Вопрос о границе
задан повторно и был лишним: уточнение терминов (`session_start` против
первого хода) нужно было сделать самому, а не спрашивать.

Поправка @NikolayXHD: правило «применение к контексту — только по явному
отдельному действию» — осознанное решение («бил по рукам каждый раз»), а не
недоделка; описание @pi-agent «дыра в логике» неверно.

### 2. Объём авто-применения

Решение: всё, что меняет текущую версию (из той же формулировки постановки).

### 4. Хоткей-переключение посреди сессии

Решение: без авто-применения; трение снимает хоткей применения (постановка:
«нужен второй хоткей для применения к контексту без открытия меню»).

### 3. Клавиша хоткея применения

Решение @NikolayXHD: `ctrl+alt+r`; `alt+r` остаётся за кольцом статусных
переменных (предложение переносить кольцо не понадобилось — забытая занятость
`alt+r`). Shift-комбинации отвергнуты: часть терминальных эмуляторов их не
передаёт. Условия приёмки — статус `!` в промежутке до первой сборки промпта и
сохранность кнопки «rewrite files on disk».
