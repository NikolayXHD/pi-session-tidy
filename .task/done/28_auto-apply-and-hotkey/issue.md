# 28 auto-apply-and-hotkey

## Постановка (@NikolayXHD)

Тезис «контекст не применяется автоматом никогда» абсурден для двух сценариев:

1. смена model / thinking перед стартом сессии — риска непреднамеренной потери
   KV-кеша нет;
2. переключение переменной хоткеем (`role`) — идея хоткея снизить трение;
   требование открыть меню и применить изменение обесценивает хоткей. Перед
   стартом сессии применим аргумент пункта 1.

Вывод: для изменений перед стартом сессии автоматическое применение шаблона —
строго верное решение. Сценарий переключения `role` посреди сессии допускает
оспаривание, поэтому нужен второй хоткей — применение к контексту без открытия
меню; это строго не ухудшающее решение второго кейса.

Требования приёмки (@NikolayXHD): статус `!` на смене модели/переменной и
правку исходника до первой сборки промпта сохраняется; кнопка «rewrite files on
disk» сохраняется.
