# 5 — Обычный и отладочный показ

Цель: @NikolayXHD читает улучшенный доклад; в отладочном режиме видит оба
текста — сырой и улучшенный, без прыжка.

Способ: обычный режим — улучшенная формулировка заменяет сырой текст при
показе; отладочный режим — улучшенный показывается блоком после исходного
(`pi.appendEntry` с рендерером). Переключатель режима — команда расширения.

Проверка: живая TUI-сессия в обоих режимах.

## Итог

Сделано @pi-agent: трансформер markdown (`pi.registerMarkdownTransformer`)
подменяет доклад улучшенной формулировкой при рендере (прыжок); в отладочном
режиме (`debug on`, команда; дефолт — поле `debug` конфига) улучшенный текст
добавляется под исходным, после разделителя. Механизм заменяет записанный в
дизайне вариант с рендерером custom entry: показ внутри того же сообщения
всегда ставит улучшенный текст сразу после исходного, без зависимости от
момента, когда расширение догнало доклад.

Проверено: живая TUI-сессия — см. ниже.

## Находка: пересборка сообщений

@pi-agent: трансформер markdown вызывается при сборке компонента сообщения —
во время стриминга, — и после этого сообщение не перерисовывается: улучшенный
текст, появившийся позже, остаётся невидимым, пока компонент не пересоберут
(resize, перезапуск). Триггер найден в pi: вызов
`ui.setHiddenThinkingLabel()` без аргумента пересобирает все сообщения —
`redrawMessages` (src/index.ts) зовёт его после применения переписки, и прыжок
происходит сам. Проверено живьём: без касаний панели текст меняется на
улучшенный после догоняющего вызова.
