## Чтение через Read tool — схема без лока

Идея верна целиком. Read tool отдаёт свой отрендеренный результат из памяти.
Запись `X` на диск нужна только для observability, локальный файл не требуется.

## Что схема не покрывает: файлы, которые читает сам pi

Не через Read tool, а напрямую с диска pi снимает:

- контекстные файлы;
- описания скилов;
- промпт-шаблоны (после загрузки с диска pi разворачивает их из своей памяти).

Здесь «отдать из памяти» не работает: память принадлежит pi, и единственный
путь в неё — файл плюс перечитывание (`reload`). Момент чтения выбирает pi, не
мы. Поэтому наше «записать для observability» фактически становится доставкой
содержимого, а окно запись → перечитывание общее для всех сессий.

## Где живёт лок

Лок живёт ровно в этом окне запись → перечитывание, и только в окнах
перерендера: старт, смена переменной, смена модели. При вызовах промптов и при
чтениях через Read tool лока нет.

## Итог

- Чтение через Read tool — твоя схема, без лока.
- Загрузчик (контекст, скилы, промпт-шаблоны) — тот же узкий лок, потому что
  единственный путь в память pi идёт через диск.
