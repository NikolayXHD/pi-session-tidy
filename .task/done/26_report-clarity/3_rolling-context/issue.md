# 3 — Рабочий контекст модели-редактора

Цель: модель-редактор всегда видит результаты уже сделанных преобразований.

Способ: запрос строится из подменённых сообщений — конспекты и переписанные
доклады стоят на месте сырых текстов; куски обоих типов обрабатываются в
порядке следования в сессии; очередь одна. Параметр `k` на рабочий контекст не
влияет.

Проверка: лог запросов показывает конспекты вместо сырых рассуждений и
переписанные доклады в префиксе следующих вызовов.

## Итог

Сделано @pi-agent: запрос фонового вызова строится из подменённых сообщений —
конспекты стоят на месте сырых блоков (`compact`, src/index.ts), значит
префикс совпадает с тем, что шлёт основная модель, и кеш провайдера общий для
них и для последующих вызовов модели-редактора. Логгер на
`before_provider_request` видит и фоновые вызовы — сверено по коду pi
(трансформ payload в общем пути провайдера).

Живой прогон конвейера конспектов после перестройки — в процессе: `k = 0`,
порог 16, три команды подряд; ждём записи `session-tidy-applied` в JSONL
сессии.

## Живая проверка

Печатный прогон на vllm/Qwen3.8 (`thinking: medium`, `k = 0`, порог 16):
один конспект применён — 82 → 73 токена, запись `session-tidy-applied` в
JSONL, запрос нёс префикс сессии (20 707 прочитанных токенов).

TUI-прогон на той же модели: конвейер прошёл всю очередь из пяти блоков —
четыре отказа «not shorter» (блоки по 20–64 токена не сжимаются), один без
обёртки `<digest>`; все отказы записаны терминально. Задача с длинными
рассуждениями: первый конспект применён — 260 → 229 токенов.

Остаток проверки — логгер запросов: первый конспект должен стоять в префиксе
следующего вызова.

## Живая проверка: итог

TUI-прогон с логгером запросов (`before_provider_request`): запросы сессии
несут конспекты — текст первого конспекта виден в запросах 2 и 3 после его
применения. Вызовы модели-редактора логгер не видит: extension-события не
срабатывают для вызовов, инициированных расширением (registry.streamSimple), —
проверено эмпирически: два вызова редактора состоялись (записи с
`spentTokens`), в логе их payload нет. Вывод: претензия TESTING.md «логгер
видит и фоновые вызовы» была неверной, документ исправлен; прямой осмотр
запроса редактора — задача наблюдаемости (подзадача 5).

Префикс редактора — та же функция подмены (`substituteMessages`), что и для
запросов сессии, и её работа подтверждена живьём на запросах 2 и 3.
