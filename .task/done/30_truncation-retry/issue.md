# 30 truncation-retry

## Постановка (@NikolayXHD)

В сессии: `Warning: tidy: report rewrite rejected — stop reason: length`.
@NikolayXHD: обещано не отклонять по длине.

## Разбор (@pi-agent)

Приёмка длину не отвергает — её отвергал бюджет вывода вызова редактора:
`maxTokens = 2 × длина исходника` при обещании «переписка может быть длиннее».
Ответ обрезался (`stop reason: length`) и отклонялся. Скрытый критерий длины.

Первый вариант правки — повтор с удвоенным бюджетом — отклонён
@NikolayXHD: игра в догадки не выигрывает ничего. Модель-рантайм зажимает
бюджет минимумом с потолком самой модели: обрезка нашим лимитом лечится одним
вызовом без своего лимита, обрезка потолком модели повтором не лечится вообще.

## Решение (@NikolayXHD)

Своего бюджета вывода расширение не задаёт: запрос идёт с потолком самой
модели. Отказ по длине возможен только с потолка модели, и называет он его
явно.

## Сделано (@pi-agent)

`editorCall` (src/index.ts) зовёт `streamSimple` с `maxTokens` самой модели
(`model.maxTokens`); `attemptBudget` и удвоения выброшены. `stopFailure`
(src/logic.ts): обрезка — терминальный отказ с причиной «the model hit its own
output ceiling». README.md и TESTING.md обновлены.
